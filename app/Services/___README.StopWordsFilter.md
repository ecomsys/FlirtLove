# Архитектура: Стоп-слова и Антифрод (Иммунная система)

Эта связка — главный щит платформы от спама, мата и мошенников. Она работает полностью в фоне, не напрягает базу данных на каждый запрос и логирует каждое действие админа.

## 1. Зачем это нужно?
В дейтинге 80% атак — это стандартные сценарии: кидать ссылки на Telegram, просить перевести деньги на карту, массовая рассылка одинаковых сообщений.

Стоп-слова — это фильтр на входе. Они проверяют текст, маскируют мат, жестко блокируют спам или "втихую" пропускают текст скамера, но стучат на него модераторам.
Антифрод — это очередь разбора улик. Модератор видит, кого словили на спаме, и банит его в один клик.

## 2. Как это работает под капотом (Поток данных)

Путь сообщения от юзера до бана скамера выглядит так:

Пользователь пишет текст (в чате, комментарии или анкете).
StopWordsFilterService:
Берет стоп-слова из кэша (Redis/File), а не из БД. Это работает за доли миллисекунд.
Проверяет текст с помощью preg_match. Если слово начинается с /, оно считается регулярным выражением.
Применяет действие: mask (замена на ***), reject (отклонить текст) или alert (собрать улики).
Очередь (CreateFraudAlertJob):
Если сработал alert, сервис отправляет задачу в фоновый воркер (на очередь antifraud). Юзер моментально получает ответ (его сообщение уходит в чат), а база не тормозит.
Воркер проверяет: «А нет ли уже открытого алерта на этого юзера за 'links_in_chat'?». Если есть — игнорирует (защита от спама БД). Если нет — создает FraudAlert.
Админка (UI):
Модератор заходит на страницу Антифрода.
Видит алерт с уликами (JSON meta), IP-адресом и сниппетом текста.
Нажимает "Вечный бан".
FraudAlertsAction:
Оборачивает логику в DB::transaction.
Банит юзера через ToggleUserBanAction.
Закрывает алерт (status = resolved).
Пишет полный отчет в AdminLog.

## 3. Ключевые архитектурные решения (Для разработчиков)

## 1. Безопасность регулярок (@preg_match)
Админ может ввести кривую регулярку в админке (например, /[a-/). Обычный preg_match вызвал бы Fatal Error и положил бы сайт. Мы используем @preg_match, который подавляет ошибку и просто пропускает правило, если оно сломано.

## 2. Кэширование Сервиса
В StopWordsFilterService метод getActiveWords() кэширует запрос к БД на 24 часа. Чат может писать тысячи сообщений в секунду, и база стоп-слов не почувствует нагрузки. При добавлении нового слова админом, StopWordsAction автоматически дергает Cache::forget('stop_words_active'), и кэш обновляется.

## 3. Защита от спама Алертов (Дедупликация)
В CreateFraudAlertJob::handle() есть жесткая проверка:

```php

 $existingAlert = FraudAlert::where('user_id', $this->userId)
    ->where('trigger_type', $this->triggerType)
    ->where('status', FraudAlertStatus::Open)
    ->exists();

if ($existingAlert) return;
```

Если бот отправит 100 сообщений со ссылкой на Telegram, в таблице fraud_alerts создастся только одна запись. База не раздует до миллионов строк.

## 4. Идеальное Логирование (Diff)
В StopWordsAction и FraudAlertsAction мы не просто пишем "Админ забанил". Мы формируем массив before и after, куда складываем полные дампы измененных данных. Если модератор удалит 5 стоп-слов, в логе будет видно, какие именно 5 слов удалили и в какой они были категории.

## 4. Интеграция в проект (Пример для Web-части)
Когда ты будешь писать контроллер для отправки сообщений в чат, код будет выглядеть максимально чисто:

```php
use App\Services\StopWordsFilterService;

public function sendMessage(Request $request, StopWordsFilterService $filter)
{
    $text = $request->input('text');
    $userId = auth()->id();

    // 1. Прогоняем через фильтр
    $result = $filter->filter($text, $userId, 'links_in_chat');

    // 2. Если текст жестко отклонен (action = reject)
    if ($result['is_rejected']) {
        return back()->withErrors(['text' => 'Сообщение содержит запрещенные элементы.']);
    }

    // 3. Сохраняем сообщение (текст уже замаскирован, если action = mask)
    Message::create([
        'body' => $result['text'],
        // ...
    ]);

    return response()->json(['success' => true]);
}
```

Тебе не нужно писать никаких if для проверки мата или скама — сервис всё сделает сам за доли миллисекунды и отправит алерт в фон.
