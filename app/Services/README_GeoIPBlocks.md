# Архитектура Гео-блокировок (Geo-Blacklist)

## 1. Зачем это нужно?

В дейтинге 90% автоматизированного спама и скама идет из конкретных регионов (Нигерия, Индия, Филиппины). Банить по IP-адресам бесполезно — они меняются за секунды.

Гео-блокировка — это иммунный щит на уровне базы данных. Она решает две задачи:

Hard Block (Жестко запретить): Отсечь ботов на этапе регистрации. Если IP из Нигерии, юзер получает 403 ошибку и даже не может создать аккаунт.
Soft Block (Скрыть из ленты): Скрыть анкеты из проблемных регионов в свайпах (теневой бан). Юзер думает, что он зарегистрировался и пользуется сайтом, но его никто не видит.

## 2. Состав системы (Файлы)

Система построена на разделении ответственности (SRP). Каждый файл делает свою работу:

Migration (geoip_locations): Единая таблица-дерево (Страны ➔ Регионы ➔ Города) с флагами is_registration_blocked и is_feed_blocked.
Model (GeoIPLocation): Содержит связи (parent/children) и скоупы для быстрой фильтрации запросов.
Service (GeoIPBlockService): Ядро системы. Кэширует заблокированные ISO-коды и ID локаций, чтобы база данных не нагружалась на каждый запрос юзера.
Action (GeoIPLocationAction): Промежуточный слой между админкой и базой. Отвечает за переключение тумблеров, сброс кэша и запись в AdminLog.
Admin UI (livewire/admin/system/geo-locations): Таблица с кнопками фильтров и тумблерами для управления правилами в один клик.

## 3. Как это работает под капотом (Flow)

Путь данных от клика админа до блокировки юзера выглядит так:

Админка (UI) ➔ Админ кликает по тумблеру в таблице Livewire.
Volt Component ➔ Достает модель GeoIPLocation по ID и передает её в GeoIPLocationAction.
GeoIPLocationAction ➔ Обновляет флаг в БД, формирует читаемый diff (с указанием родительской страны), пишет лог в AdminLog и дергает метод GeoIPBlockService::clearCache().
GeoIPBlockService ➔ Сбрасывает кэш Redis/Database. Старые правила удаляются.
Контроллер Регистрации (Web) ➔ При следующем запросе юзера сервис видит пустой кэш, идет в БД, берет свежие заблокированные ISO-коды, кладет в кэш на час и возвращает результат. Если страна в бане — кидает 403.
FeedService (Web) ➔ При формировании ленты сервис запрашивает массив заблокированных ID, и через User::whereNotIn('region_id', ...) скрывает скамеров из выдачи.

## 4. Как интегрировать это в Web (Примеры кода)

## Вектор 1: Защита при Регистрации (Hard Block)
В контроллере регистрации (или в Middleware) мы проверяем IP юзера через пакет stevebauman/location. Если страна в черном списке — отказываем в доступе.

```php

use Stevebauman\Location\Facades\Location;
use App\Services\GeoIPBlockService;

public function register(Request $request)
{
    // 1. Получаем гео по IP
    $location = Location::get($request->ip());
    $countryCode = $location?->countryCode;

    // 2. Проверяем через наш кэшируемый сервис
    $geoService = app(GeoIPBlockService::class);

    if (!$geoService->isRegistrationAllowed($countryCode)) {
        abort(403, 'К сожалению, сервис недоступен в вашей стране.');
    }

    // ... логика создания юзера
}
```

## Вектор 2: Скрытие из Ленты / Свайпов (Soft Block)

В сервисе, который собирает анкеты для ленты, мы исключаем юзеров, чьи country_id, region_id или city_id попали в черный список.

```php
use App\Services\GeoIPBlockService;

public function getFeed(User $user)
{
    $geoService = app(GeoIPBlockService::class);
    
    // Получаем массив ID заблокированных локаций (из кэша!)
    $blockedGeoIds = $geoService->getFeedBlockedIds();
    
    return User::query()
        ->where('id', '!=', $user->id)
        // Исключаем юзеров, кто сидит в заблокированных регионах
        ->when(!empty($blockedGeoIds), function ($q) use ($blockedGeoIds) {
            $q->whereNotIn('country_id', $blockedGeoIds)
              ->whereNotIn('region_id', $blockedGeoIds)
              ->whereNotIn('city_id', $blockedGeoIds);
        })
        ->inRandomOrder()
        ->limit(20)
        ->get();
}
```

## 5. Инструкция для Админов (Как управлять)

Зайди в админку ➔ Система ➔ Гео-справочник.
По умолчанию открыта вкладка "Страны" (чтобы не грузить тысячи городов). Можно переключить на "Регионы СНГ".
Вбей в поиск "Нигерия" или её ISO-код "NG".
Включи красный тумблер (Запретить регистрацию) или желтый (Скрыть из ленты).
В этот момент система обновит базу, сбросит кэш и запишет лог.
Новое правило вступает в силу мгновенно для всех новых регистраций и запросов ленты.

## 6. Используемые пакеты и Локализация (Для разработчиков)
В этой системе мы используем два сторонних пакета. Важно понимать, как мы их применяем, чтобы не нарушать архитектуру проекта.

## Пакет 1: stevebauman/location (Определение IP)
Зачем нужен: Превращает сырой IP-адрес (например, 102.89.23.10) в удобный ISO-код страны (NG).
Как мы применяем: Мы используем его только в контроллерах веб-части (например, при регистрации). Мы не храним IP-адреса в базе для блокировок, так как они меняются за секунды. Мы один раз получаем от пакета countryCode и сразу сверяем его с нашим кэшем заблокированных стран.

## Пакет 2: nnjeim/world (Справочник стран)
Зачем нужен: Содержит полную базу всех стран мира, регионов и городов с их ISO-кодами.
Как мы применяем (Паттерн Data Sync): Мы не используем таблицы пакета (countries, states) в боевой работе приложения. Команда php artisan migrate:fresh сносит все таблицы, включая таблицы пакета.
Чтобы наша система гео-блокировок не зависела от чужих миграций, наш GeoIPLocationsSeeder один раз читает данные из пакета и раскладывает их в нашу собственную таблицу geoip_locations. Это изолирует нашу систему от багов стороннего кода.
Локализация (Переводы стран)
У нас в проекте принято хранить переводы в корневой папке /lang. Но пакет nnjeim/world по стандартам Laravel публикует свои файлы переводов в resources/lang/vendor/world/ru/country.php.

Чтобы всё работало красиво и по стандартам фреймворка, мы сделали две вещи:

Объединение путей в AppServiceProvider:
Мы жестко указали Laravel искать наши переводы в корне:
php
```php
$this->app->useLangPath(base_path('lang'));
```
Использование Namespace в Blade:
В базе данных мы храним только оригинальное (английское) название страны и её ISO-код (например, RU). Чтобы в админке выводилось "Россия", мы не пишем костылей в сидере. Мы используем встроенный механизм Laravel для переводов вендоров — двойное двоеточие:
blade
```php
__('world::country.' . $loc->iso_code)
```
Laravel сам заходит в resources/lang/vendor/world/ru/country.php, находит там ключ RU и выводит "Россия". Если мы поменяем язык сайта на английский, страны автоматически переведутся на English без изменения кода.
