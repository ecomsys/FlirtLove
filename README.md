

# Добро пожаловать в проект FlirtLove!

Этот гайд поможет быстро развернуть локальное окружение и запустить все сервисы одной командой.


## Минимально необходимые расширения для VS-Code:
```bash
1.Laravel Blade Snippets - даст VS Code грамматику языка Blade 
2.Blade Formatter — чтобы Shift+Alt+F красиво форматировало Blade, а не ломало его. 
3.Tailwind CSS IntelliSense — автоподсказка классов. 
4.PHP Intelephense — лучший автокомплит для PHP. 
5.Prettier — для форматирования JS/JSON/CSS. 
6.ESLint
```

## Минималоьный список расширений раскомментированных рсширений в php.ini

```bash
extension=curl

extension=gd

extension=mbstring
extension=openssl
```

и

```bash

```

## Требования

```bash
PHP ≥ 8.1 (с расширениями: pgsql, pdo_pgsql, zip, gd, mbstring, json, curl, fileinfo)
Composer (установщик зависимостей PHP)
Node.js ≥ 18 (для Vite и npm)
PostgreSQL ≥ 13 (или 14, 15)
Git (для клонирования)
Git Bash (рекомендуется для Windows, но не обязательно)
```

## Клонирование репозитория

```bash
git clone https://github.com/ecomsys/FlirtLove.git
cd Flirtlove
```

## Установка зависимостей

```bash
composer install
npm install
npm run build 
cp .env.example .env
```

## Отредактируйте .env — укажите данные для подключения к PostgreSQL:

```bash
DB_CONNECTION=pgsql
DB_HOST=127.0.0.1
DB_PORT=5432
DB_DATABASE=flirtlove_db
DB_USERNAME=ваш_пользователь
DB_PASSWORD=ваш_пароль
```

## Создайте базу данных, если её ещё нет. Можно через терминал:
```bash
createdb flirtlove_db
```
Или через pgAdmin / Adminer.

Что она делает ? Ровно :
```bash
npm run dev
php artisan serve
php artisan shedule:work    #  Планировщик задач - worker (отправка уведомлений и др.)
php artisan queue:work      #  Очередь заданий - worker (модерация фоток и др.)

```

# Вот полная схема админ-панели для нашего дейтинга.

📌 Глобальная структура сайдбара (Меню)
Меню группируется по доменам бизнеса, а не по таблицам БД.

📊 Дашборд (Главная)
👥 Пользователи (Ядро)
🛡️ Модерация (Очереди日常工作)
💬 Коммуникация (Чаты и Контент)
💳 Финансы (Монетизация)
🚨 Безопасность (Антифрод)
⚙️ Система (Настройки и Логи)

1. 📊 Дашборд (Главная страница)
Цель: Быстрый срез здоровья проекта с утра.

Виджеты (Карточки):
Новые юзеры (за 24ч / 7д).
Онлайн прямо сейчас.
Выручка (за 24ч / 30д).
Очередь модерации (Сколько фото/верификаций/жалоб висит в pending).
Графики:
Регистрации (линейный за 30 дней).
Выручка (за 30 дней).
Активность (Свайпы / Мэтчи / Сообщения за неделю).

2. 👥 Пользователи
Цель: Поиск, просмотр и управление анкетами.

Страница "Все пользователи":
Таблица: ID, Аватар, Имя, Пол, Город, Статус, Premium, Верификация, Создан.
Фильтры: По статусу (active, banned), по роли, по полу, по городу, по наличию VIP, по онбордингу.
Массовые действия: Забанить выбранных, выдать VIP.
Страница "Профиль юзера" (ID: 123) -> ТАБЫ (Вкладки):
Таб "Анкета": Редактирование полей профиля, назначение роли, ручная смена пароля.
Таб "Статус и Баны": Кнопки "Забанить" (с выбором причины и срока), "Зашадоубанить", "Снять бан".
Таб "Фото": Галерея всех фото юзера. Возможность approve/reject прямо отсюда. Назначить фото аватаркой.
Таб "Финансы": Баланс кредитов, история транзакций, подписки. Кнопка "Начислить кредиты" (ручное пополнение).
Таб "Социальный граф": Список его мэтчей, кого он заблокировал, кто заблокировал его, просмотры анкеты.
Таб "Дневник": Его посты (с возможностью редактировать/удалять админом).
Таб "Жалобы": Жалобы от этого юзера и жалобы на этого юзера.

3. 🛡️ Модерация (Очереди)
Цель: Рабочий стол модератора. Никаких списков — только очереди pending-записей.

Очередь "Фотографии": Сетка (Grid) фото со статусом pending. Кнопки: ✅ Одобрить, ❌ Отклонить (с выбором причины: порно, детское, реклама, чужое).
Очередь "Верификация": Список заявок на "Синюю галочку". Открыть фото с паспортом -> ✅ Одобрить / ❌ Отклонить (размыто, фейк).
Очередь "Комментарии": Комментарии со статусом pending или превысившие reports_count.
Жалобы (Reports): Таблица жалоб. Фильтр по статусу (pending). Открытие жалобы -> просмотр контекста (кто на кого, за что) -> Разрешить (бан/варн) или Отклонить (ложная тревога).

4. 💬 Коммуникация
Цель: Контроль переписок и контента.

Чаты: Поиск по ID/имени. Просмотр переписки (для разбора жалобы или саппорта). Возможность писать от лица Саппорта.
Дневники: Список всех постов. Модерация (снять с публикации, удалить).
Рубрики: Справочник рубрик для дневников (CRUD).
Стоп-слова: Управление словарем. Таблица: Слово, Категория, Действие (mask/reject/alert).

5. 💳 Финансы
Цель: Деньги, подписки и виртуальная экономика.

Транзакции: Таблица всех платежей. Фильтры (успешные, возвраты, по дате). Кнопка "Оформить возврат" (Refund) с указанием причины.
Подписки (VIP):
Список покупок юзерами.
Тарифы (Справочник): Создание/редактирование тарифов (название, цена, фичи JSON, Apple/Google ID).
Подарки (Справочник): Каталог подарков (Название, цена в кредитах, картинка, статус активности).

6. 🚨 Безопасность
Цель: Борьба с ботами, скамерами и мошенниками.

Антифрод-Алерты: Очередь сработавших триггеров (с критичностью High наверху). Разбор: принять (забанить) или отклонить (ложняк).
Блокировки (Черный список): Аналитическая страница. Кто кого блокирует. Выявление юзеров, которых массово блокируют (маркер проблемного юзера).
Устройства и IP: (Вывод данных из users.device_id и last_login_ip для поиска мультиаккаунтов).

7. ⚙️ Система
Цель: Настройка проекта и аудит.

Настройки (Settings): Динамическая форма, сгруппированная по вкладкам (General, Limits, Moderation, SEO, Social). Поля генерируются из БД (type: text, boolean, number).
Страницы (Pages): WYSIWYG-редактор для Политики, Оферты, О нас.
Рассылки (Broadcasts): Создание кампании (выбор аудитории по фильтрам, тип in-app/email/push). Просмотр статистики отправки (сколько ушло, сколько упало).
Логи Админа (Audit Trail): История всех действий администрации (Кого забанил, что изменил в настройках). Диффы (Было/Стало).
Логи Системы: Просмотр storage/logs/laravel.log (чтение файла, как в Laravel Log Viewer).
💡 Ключевые UI/UX паттерны для реализации:
Действия на месте (Actions in Place): Модератор не должен переходить на новую страницу, чтобы забанить юзера. Кнопка "Забанить" должна быть модалкой или SlideOver панелью прямо в списке или карточке.
Контекстные breadcrumbs: Всегда понятно, где мы находимся (Пользователи -> Иван Иванов -> Финансы).
Soft Delete превью: В списке юзеров забаненные/удаленные должны быть выделены красным/серым цветом и с бейджом, чтобы визуально отделялись от активных.
Бейджи статусов: Один компонент для статусов (Active = зеленый, Banned = красный, Pending = желтый). Использовать наш аксессор getStatusBadgeAttribute().
